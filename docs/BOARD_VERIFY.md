# PQM2 上板验证清单

面向"板子在手、要按顺序验一遍"的人。每一步都给命令、期望值和修前对照值。
文末有「哪些已在 2026-09-28 实测通过、哪些还没看」。

## 0 前置条件

- 板子通电，JTAG（Digilent JTAG-HS1）接好；运行前确认没有别的进程占着 hw_target。
- 信号源接 AD7606 输入端，**输出阻抗设高阻（Hi-Z），不要设 50 Ω**。
  实测踩到：发生器面板按 50 Ω 标定时，同一路读数会偏大 2 倍（板子的 ADC 输入是高阻，没有 50 Ω 端接负载）；改 Hi-Z 后 6 Vpp 设置对应 6.06 Vpp 读数。
- 板上 AD7606 是**电压** ADC，两路输入共用同一前端、满量程 ±10 V（无衰减）。U2 通道由 PS 直接当电流显示，折算系数 1。

## 1 生成产物（若 `build/`、`export/` 是空的，先做这一步）

```powershell
# 1.1 Vivado：产出 vivado/pqm2_meas.xsa 与 vivado/pqm2_meas.bit（约 25–30 分钟）
New-Item -ItemType Directory -Force vivado\build_meas | Out-Null
cd vivado\build_meas
& 'D:\zt\Xilinx\Vivado\2022.2\bin\vivado.bat' -mode batch -source ..\scripts\build_meas.tcl
#    阶段由环境变量 MEAS_STAGE 控制：bd / synth / all（默认 all）

# 1.2 从 XSA 生成 Vitis 工作区并编译应用
powershell -ExecutionPolicy Bypass -File scripts\build_app.ps1
```

`build_app.ps1` 结束时必须打印两条硬校验（缺一条就说明编错了东西）：

```
校验 1 通过：makefile 已包含 src/pqmshm/subdir.mk
校验 2 通过：<elf> 含符号 PQMUI_ShmPoll
```

要确认的三个产物：

| 产物 | 路径 |
| --- | --- |
| 比特流 | `build/vitis_ws_meas/pqm2_hw/hw/pqm2_meas.bit` |
| ps7 初始化脚本 | `build/vitis_ws_meas/pqm2_hw/hw/ps7_init.tcl` |
| 应用 ELF | `build/vitis_ws_meas/pqm2_app/Debug/pqm2_app.elf` |

> `vivado/pqm2_meas.xsa` 与 `.bit` 是构建产物、已 gitignore，不进版本库；写这份文档时工作区里没有它们，必须先跑 1.1。
> **比特流和应用 ELF 必须配套**：ELF 里引用的 `axi_gpio_0`(0x41200000)、`clk_wiz_0`(0x43C00000) 只存在于测量版的 BD 里。拿别的比特流配这份 ELF 会全黑屏（只剩背光）。

## 2 烧录

```powershell
& 'D:\zt\Xilinx\Vitis\2022.2\bin\xsdb.bat' scripts\flash_meas.tcl
```

脚本按这个顺序做，日志同时写 `export/board_meas.log`：

1. 连 JTAG；冷启动时 DAP 可能停在错误态，脚本会经 DAP 发系统复位解锁；
2. **复位整个 PS**（这一步是必须的，见文末「两个已知陷阱」）；
3. 编程 PL（`fpga -file`）；
4. `ps7_init` + `ps7_post_config`，失败会自动系统复位重试（最多 4 次）；
5. `rst -processor` 后下载 ELF 并 `con`；
6. **等 10 秒**（测量间隔 16e6 拍 @50 MHz = 0.32 s，谐波帧要跑几帧才稳；零点跟踪器时间常数约 0.64 s，上电瞬态要等掉）；
7. 读显示通路寄存器；
8. 抓两次共享内存（间隔 1 s），写 `export/shm_words_1.txt`、`export/shm_words_2.txt`。

### 判据 A：显示通路寄存器与官方基线逐项吻合

| 寄存器 | 地址 | 期望 |
| --- | --- | --- |
| axi_gpio（LCD ID） | `0x41200000` | 读到值即可（本板为 0） |
| clk_wiz_0 | `0x43C00000` | `00000A01` |
| VDMA CR | `0x43000000` | `0001400B` |
| VDMA SR | `0x43000004` | `00011000` |
| VDMA MM2S 起始地址 | `0x4300005C` | `01100000` |
| VTC 状态 | `0x43C10004` | `00013000` |
| 共享内存 magic | `0x40000000` | `50514D31` |

**只要 `VDMA CR=00010002`、`VTC=0`，就说明应用没跑到显示初始化**（多半是 ELF/比特流不配套，或上一步的系统复位被跳过），画面不会更新 —— 先解决这个，后面的项都没意义。

## 3 读测量值

```powershell
pwsh -File scripts\report_shm.ps1
```

### 判据 D：读的是活数据

`report_shm.ps1` 末尾会对比两次抓取：

| 计数器 | 2026-09-28 实测 |
| --- | --- |
| snap_seq | 145 → 163 |
| harm_gen | 676 → 765 |

两个都必须递增；不递增说明读到的是死内存。

### 判据 E：倍率换算（大量程）

界面上显示的是「真值 × K」，K = 220√2/8 = **38.89**，功率 × K² = **1512.43**（小量程 K=1，显示真值）。
用上面那组真值核对：

| 界面字段 | 真值 | 应显示 | 2026-09-28 实测 |
| --- | --- | --- | --- |
| U RMS | 6.36 V | 247.4 V | 该轮没抓到界面读数；换倍率以后的那轮真值是 3.20 V，界面显示 124.44 V（= 3.20 × 38.89 ✓） |
| I RMS | 4.94 V | 192.1 A | 192.11 A（= 4.94 × 38.89 ✓） |
| 有功 P | 15.71 W | 23760 W | 该轮没抓到界面读数；换倍率以后的那轮真值是 7.89 W，界面显示 11933.07 W（= 7.89 × 1512.43 ✓） |

| 项 | 期望 |

| 项 | 期望 |
| --- | --- |
| 标题 | `PQM - Frequency Domain` |
| 幅度图 | 只有存在的谐波画柱（占比为 0 的槽不画 0 高度柱，避免底部"梳齿"） |
| 横坐标刻度 | **每根谐波都标**：`0 1 2 … 15`（16 个）；翻页后 `16..31` / `32..47` / `48..63` |

| 页码标签 | 第 1 页 `H0 - H15` |

修前症状：没有任何横坐标刻度；0 线与底轴是相隔约 10 px 的两条线；相位图每根柱都从自己的相位值一路拉到 −180（整张图读的是"离 −180 还有多远"）；零幅值谐波的相位在 27°~74° 的标准差上乱跳。

### 判据 H：翻页与小量程

需要点按钮。触摸是 FT5206 走 I2C，**JTAG 注入不了真实触摸**，但可以用 `scripts/inject_touch.tcl` 经 JTAG 伪造：

```powershell
& 'D:\zt\Xilinx\Vitis\2022.2\bin\xsdb.bat' scripts\inject_touch.tcl <屏幕x> <屏幕y>
```

原理：`lv_port_indev.c` 的 `touchpad_is_pressed()` 每 30 ms 都调 `tp_dev.scan()`，直接写 `tp_dev.sta` 会被立刻覆盖；脚本先把函数指针 `tp_dev.scan` 临时指到 `Xil_DCacheFlush()`（无参数、无副作用的空操作），注入 `sta`/`x`/`y` 后还原。

| 目标 | 屏幕坐标 | 点完应看到 |
| --- | --- | --- |
| `Spectrum` / `Time` 切页 | (611, 22) | 标题在 `PQM - Time Domain` ↔ `PQM - Frequency Domain` 之间切换 |
| `Freeze` / `Resume` | (726, 22) | 按钮文案变化，数值停止刷新 |
| 时域页量程按钮 | (243, 434) | 大量程 `389 V / 389 A` ↔ 小量程 `10 V / 10 A`；纵轴 `±389` ↔ `±10`；数值切到真值 |
| 频域页上一页 `<` | (72, 435) | 页码标签与刻度整体前移 16 |
| 频域页下一页 `>` | (438, 435) | 页码标签与刻度整体后移 16 |

> `inject_touch.tcl` 顶部的三个符号地址（`tp_dev` / `Xil_DCacheFlush` / `FT5206_Scan`）**随每次重新编译变化**，脚本头部注释给了重新取值的 `nm` 命令。

## 5 2026-09-28 实测结果

**已验证通过**：判据 A、B、C、D、E、F、G（频域页第 1 屏）。

**还没看**：

- 判据 H 里的**小量程页**与**谐波翻页**（当时触摸得手点，写这份文档时已有 `inject_touch.tcl`，可以补）。
- `Freeze` / `Resume`。
- 边界条件：阈值附近的小信号、上电瞬态、掉采样计数（`drop_count`）在异常激励下的行为。

**不要拿下面这个当缺陷**：验证过程中操作者把发生器 CH1 改成了畸变波形，那一轮实测是
`Fundamental 249.96 Hz`、`THD-U 85.02 %`、U 谐波 `H1 45.26 % / H5 27.12 % / H7 27.11 %`，而 CH3 干净（`H1 99.78 %`）。
操作者明确说明这是他改的波形。**频率只在"稳态纯正弦"下按 50.00 Hz 判**。

## 6 两个已知陷阱

1. **`ps7_init` 之前必须复位整个 PS**。如果 DAP 是健康的、上一次烧的应用还在跑，它的 SCU 定时器与 GIC 使能位仍然有效；直接盖一遍 `ps7_init` 会把残留中断留给新应用 —— 新应用在 `timer_init()` 注册 `XIL_EXCEPTION_ID_INT` **之前**就吃到 IRQ，直接落进 `Xil_ExceptionNullHandler`（实测 PC = `0x001a0d1c`、CPSR 停在 IRQ 模式），显示通路一行都跑不到（`VDMA CR=0x00010002`、`VTC=0`）。`flash_meas.tcl` 已改成无条件先复位、并在 `dow` 前补 `rst -processor`。
2. **应用上电默认停在时域页**。要抓频域页的帧，必须先切页（`inject_touch.tcl 611 22` 或手点），否则抓到的是时域页。
