## 1 背景与问题

### 1.1 电能质量监测要测什么

电网是标称 50 Hz 的单相/三相正弦，但真实波形里叠着整数次谐波、间谐波、噪声、尖峰与暂降。工程上要回答的问题集中在这些量：

- **基波频率**，以及它与标称值的偏差（实际可能在 49.8 Hz、50.2 Hz 附近漂移）；
- **各次谐波的幅值占比**，且至少覆盖到第 50 次（50 Hz 基波对应 2500 Hz）；
- **各次谐波的相位**，以及由此导出的 U-I 相位差、有功/无功/视在功率与功率因数；
- **总谐波畸变率 THD**，定义为

  $$\mathrm{THD}_U=\frac{\sqrt{\sum_{h\ge2}U_h^2}}{U_1}\times100\%$$

  它同时依赖基波幅值 $U_1$ 与各次谐波幅值 $U_h$，因此基波或高次谐波中任何一处算错，THD 都会跟着失真。

（谐波的定义、THD 公式与"频偏会让高次谐波按阶次累积失配"的说明，引自 `Goertzel_FPGA/docs/project_learning_guide.md` §2。）

### 1.2 传统方案在实时性与确定性上的短板

三类常见做法各有硬伤：

| 方案 | 主要问题 |
| --- | --- |
| PC / 工控机上的软件 FFT | 需要操作系统调度，单次分析的完成时刻不确定；要同时覆盖 50 次谐波且实时刷新，CPU 负载与延迟都不好保证 |
| 通用 DSP 芯片 | 逐点运算仍是串行指令流，多通道 × 多算法要按时间片轮转；达到同样的实时性要拉高主频，功耗随之上来 |
| 专用 ASIC | 流片成本与周期长，算法一改就得重新投片，不适合研究/迭代型项目 |

共同的根源是：**它们是"按时序一条条执行"的**。而谐波分析恰好是"每个采样点都要做同一批乘加"这种天然可并行的结构，串行执行把时间浪费在重复取指与调度上；更麻烦的是**完成时刻不确定**——一旦某一帧晚到，后续按帧对齐的处理（相位累加、双缓冲提交）就会错位。

本工程选择 FPGA，正是要换掉这两个约束：把测量链做成**固定结构的硬件流水线**，让"耗时"变成可以精确到拍（50 MHz 下 20 ns）的常数。

## 2 项目定位

### 2.1 是什么

PQM2 是一台基于 **Zynq XC7Z020-CLG400-2** 的电能质量分析仪工程，位于 `C:\Users\zhangtao\Desktop\PQM2`。它的定位由两条边界确定（`README.md`）：

- **硬件与板级驱动的基线**是正点原子官方例程 `37_zynq_lvgl`（视频段 BD、LCD/VDMA/VTC 驱动、LVGL 8.2.0、触摸驱动等原文件原编码使用）；
- **PS 界面**按旧工程 `C:\Users\zhangtao\Desktop\PQM` 的规格**严格像素级等价**重实现——只改代码层面，画面不动；
- **PL 测量链是自研的**，频域不再使用厂商 xfft IP。

### 2.2 PS + PL 的分工

Zynq 的价值在于同一颗芯片里既有 ARM 处理器（PS）又有可编程逻辑（PL）。PQM2 把两者切得很干净：

| 部分 | 承担什么 | 为什么放在这里 |
| --- | --- | --- |
| **PL**（`pl/rtl/`） | 采样控速、ADS7606 驱动、零点跟踪、时域测量、频域分析（RFG）、共享内存桥 | 这些是**每个采样点都要跑**的固定运算，结构确定、延迟可算；放 PL 才能拿到确定性时序 |
| **PS**（`app/`） | LVGL 界面、触摸、显示通路、量程与倍率换算 | 这些是**人机交互与显示**，逻辑分支多、时序要求松，放 CPU 更省事也更易改 |

两边的接口只有一个：**PS/PL 共享内存**（`0x40000000`，16384 字 × 32 bit），见 §3.7。PL 只往里面写"原始工程量"，PS 负责把它翻译成人看得懂的显示值。这条约束带来一个很实际的好处：**改显示口径完全不用重新综合 PL**——例如本工程把模拟市电倍率从 27.5 改成 38.89，只重编了 ARM 应用，比特流一个字没动。

## 3 测量原理

### 3.1 信号链总览

```
                     ┌─────────────── PL（50 MHz，全自研）───────────────┐
信号源 ──±10 V──► AD7606 ──并行采样──► pqm_adc_pacer（25.6 kHz 控速）
                     │
                     ├─► time_zero_code_tracker ×2（U1/U2 动态零点）
                     │
                     ├─► 时域链：RMS / 峰峰值 / 相位差 / 功率 / 频率
                     │
                     └─► 频域链：FIFO → RFG 前端 → 归一 → 幅值 → 谐波统计
                                  → 相位矢量 → 相位查表 → IIR 滤波
                     │
                     ▼
              pqm_shared_memory_bridge ──► 共享内存 0x40000000
                     │
                     ▼
                     └─────────────── PS（ARM + LVGL，100 MHz AXI）────────┘
                         app/pqmshm（读共享内存） → app/pqmui（LVGL 界面）
```

构成 PL 顶层的模块见 `pl/rtl/PQM_TOP/pqm_pl_top.v`：`pqm_adc_pacer`、`AD7606_Parallel_DRIVER`、两个 `time_zero_code_tracker`、`pqm_measurement_core`、`pqm_shared_memory_bridge`、`pqm_range_command_controller`。

### 3.2 采样控速：为什么必须显式做 25.6 kHz

频域分析取 **N=512** 点，而 512 点要正好覆盖**一个 50 Hz 周期**，所以采样率必须是

$$f_s = 512 \times 50 = 25600\ \text{Hz} = 25.6\ \text{kHz}$$

对应到 50 MHz 时钟就是每 **1953.125 拍**采一个点。这个数不是整数，所以不能靠"数够拍数就采"来实现。`pqm_adc_pacer`（`pl/rtl/ADC_PARALLEL/pqm_adc_pacer.v`）用**26 位小数分频累加器**：每个时钟加 `INC = 34361`，溢出即输出一个 1 拍宽的 tick。

- 为什么 `INC = 34361`：由 `周期拍数 = 2^W / INC` 反解，`2^26 / 1953.125 = 34359.738`，取最近且能给出正确 Bresenham 交替的整数。
- 为什么是"平均严格"而不是"每次都准"：`1953.125 = 15625/8`，而 `15625 = 5^6` 与 2 互素，所以 `2^W/INC` **不可能**精确等于 1953.125。真正的判据是**整数拍窗口内脉冲数恰好为整数**：15625 拍内恰好 8000 个脉冲。
- 抖动：相邻间隔只取 **1953 或 1954 拍**（±20 ns @50 MHz），长时无累积误差。

> 这里有一处**旧交接文件自身的错误**被本工程查实并纠正：原文写的增量 `1953125 = 1953.125 × 1024` 把周期乘了 1024，量纲不对；它在 26 位下给出 34.36 拍/脉冲（1.455 MHz），与 25.6 kHz 差 57 倍。

仿真验收（`pl/sim/ADC_PARALLEL/tb_pqm_adc_pacer.v`）：1786 个间隔跨 3488153 拍（理论同值）、间隔只取 1953/1954、15625 拍标定窗内恰好 8 个脉冲、复位释放到首脉冲 1954 拍。

### 3.3 时域零点跟踪（`time_zero_code_tracker`）

AD7606 输出的是**偏移二进制**：理论零点在 `0x8000`。但实际器件的零点会随温度、基准漂移，且前端可能有直流偏置。如果直接拿 `0x8000` 当零点去算 RMS 与 DC，这些偏置会整个计进结果——本工程就曾在板上测到 **28.67% 的假直流**（见 §7）。

`time_zero_code_tracker` 的做法是**动态跟踪真实零点**：

- 复位后从 `0x8000` 开始；
- 预热阶段用较快的 `WARMUP_SHIFT` 快速收敛到真实中心，减小上电后的波形偏移；
- 预热完成后切回较慢的 `EST_SHIFT`，避免零点跟踪过快地把交流幅值也"吞掉"；
- 为保证误差小时不完全停滞，最小修正步长保持 1 个码值。

关键实现细节：**移位必须向零舍入（sign-magnitude），不能用 floor**。用 floor 会让修正步长恒为非奇数（偶数减 1 后又被 floor 抹掉），纯 AC（零直流）输入下零点会停在 28132 而不是 `0x8000`。这正是上面那个 28.67% 假直流的根因，改成向零舍入后残差降到 127 码。

### 3.4 频率测量：过零 + 施密特迟滞 + 线性插值

`frequency_measure.v`（`pl/rtl/.../TimeAnalysis/RawDataCal/`）在**一次采样窗口内**检测 U1 的正向过零事件，对每次过零做亚采样精度的插值，再算周期。

**判据（施密特触发器）**：以 `ref_code`（零点跟踪有效时用它，否则用中心码）为参考，迟滞 `±FREQ_HYST`（`WIDTH=16` 时 `FREQ_HYST = 2 << 8 = 512` 码）：

```
code <= ref - HYST            -> 置 armed（确认信号确实在参考点下方）
armed 且 code >= ref + HYST   -> 判为一次正向过零，清 armed
```

要求"先 armed 才找过零"，所以窗口开头那半个不完整的半周不会被误判。

**插值**：记 anchor = 最近一个 `code < ref` 的采样点，过零落在 anchor 与当前采样点之间：

$$\text{frac}=\frac{ref-a_{code}}{c_{code}-a_{code}},\qquad t_{cross}=a_{clk}+(c_{clk}-a_{clk})\cdot\text{frac}$$

由于过零判据保证 $c_{code}\ge ref+HYST$ 且 $a_{code}\le ref-1$，分母 $\ge HYST+1>0$、分子 $\in[1,ref]$ 且小于分母，**插值不会退化**——噪声让相邻两采样值互相靠拢也不会出现除零或溢出。`frac` 用 12 位定点小数（`FRAC_BITS=12`）由逐位长除法产生。

**周期**：窗口内只保留首次与末次两次过零，窗口结束后用同一个移位-相减除法器依次算

$$\text{周期}=\frac{t_{last}-t_{first}}{N_{cross}-1}$$

输出 `freq_period_raw`（一个基波周期的时钟计数）。过零次数 <2 或时间差非正时只给 `done`，不给 `freq_valid`。

**它为什么比"峰间隔法"稳**：这是本模块头注释里记录的一段真实历史。旧实现是"半周内找最大值当峰、测峰-峰间隔"，它有**两个互相错开的门限参考系**——武装用零点 `ref_code`，峰值确认用"峰顶 − 迟滞"。当"从峰顶回落超过迟滞"恰好落在过零点附近时，确认时刻被推迟到零点，而零点又是武装事件发生的同一拍，两者互相吞掉，于是有概率整个半周不出峰，读数在真值与 2 倍附近随机跳（板上实测：信号源稳定 50 Hz 时读数在 **52~85 Hz** 之间乱跳）。

换成过零判据后有两个结构性好处：**正向过零在每个基波周期必然发生且只发生一次**，没有"跳过"的余地；而且"首末过零差分"会把 AM、谐波、直流引起的**固定相位偏移整体抵消**掉。

**固有局限（必须写明）**：该方法测的是**过零穿越率**。当波形含强 5/7 次谐波时，一个基波周期内会多出几对零点，穿越计数给出的就不再是基波频率。本工程实测过一次强畸变输入读到 **249.96 Hz**——那次波形是操作者自己改的，明确不算缺陷（`docs/BOARD_VERIFY.md` §5），但它是一条真实的**口径限制**：若要覆盖畸变波形，应改用 RFG 的 1 号 bin 定频率，或加大迟滞/取主周期。**该限制当前未修**。

### 3.5 时域测量

`pqm_measurement_core`（`pl/rtl/DataProcessor/pqm_measurement_core.v`）在 PS 显示模式下保留确定性的时域测量、频域谐波统计与骤变告警，直接生成共享内存标量快照与谐波流，**不实例化任何 PL 显示或文本格式化逻辑**。

- 测量窗口：`MEASURE_FRAME_SAMPLES = 6144` 个样本；
- 启动间隔：`MEASUREMENT_INTERVAL_CYCLES = 16_000_000` 拍 @50 MHz = **0.32 s**（`pl/rtl/PQM_TOP/pqm_pl_top.v`）；
- 输出的标量字段：频率、U1/U2 RMS、U1/U2 峰峰值、相位、有功/无功/视在功率、功率因数、THD-U/THD-I、DC-U/DC-I。

**一处必须写清的口径**：PL 只产出 **U1/U2 两路真实电压值**，固定满量程 10.00 V（x100 = 1000），**不做量程切换**；PL 里已不再区分 U/I。U2 由 PS 直接当电流显示，折算系数 1。为此 `full_scale_low_range_active` 端口已不参与任何换算，只为不牵动顶层与 BD 端口表而保留（未使用）。

`pqm_measurement_core` 里还处理了一处会致命影响 THD 的**位宽缺陷**：频率中心化量的 17 位乘积原本被截成 `[15:0]`，只要 `|sample - zero| > 32767` 就回绕；18 Vpp 正弦下板上实测 **THD-U 报 180.67%**。改为饱和后降到 0.03%，并把饱和/溢出粘滞位写进 validity（见 §3.7）。

### 3.6 频域分析：RFG 链

频域链是**全自研、无厂商 IP** 的（`pl/README.md`「频域链改用 RFG」）：

```
ADC 采样流 → pqm_sample_fifo（每通道 64 深）→ pqm_rfg_frontend（2× RFG + 2× 直流累加器）
           → pqm_rfg_scale（>>10，变成 16 位频点流）→ magnitude_calc
           → harmonic_stats → phase_vector_calc → phase_deg_lut_calc
           → freq_harmonic_iir_filter
```

取点 **N=512、K=64**，只算 1~64 次谐波。后级五个模块是从原 xfft 路线**一字未改直接复用**的。

已经在工程里查实、值得单独记下的三条：

1. **RFG 只认样本序列、不认时间**。它算的是"连续 N 个采样点的 DFT"；若上游在它未就绪时把采样丢掉（计算期 `o_sample_ready` 为低），一帧的 N 个点就不再连续、会跨多个周期，谱随之泄漏。**实测**：自由跑激励下 1 次 u 占比从 7142 掉到 **2508**，并冒出 5 次 **873** 的假谱线；前面加 FIFO 后同一激励精确通过（7153 / 2846 / 10000 / 相位差 9006）。FIFO 深度依据：25.6 kSPS 下 L4/D1 的计算期 83840 拍 ≈ 43 个采样。
2. **RFG 不输出 bin 0**，直流由 `pqm_rfg_dc_sum` 补（一个加法器 + 寄存器 + 左移 1 位），标度与各 bin 严格一致。
3. **`pqm_rfg_scale` 必须四舍五入而非截断**：截断的负偏置会抬高总幅值、把所有占比整体压低（实测 1 次 u 由 7142 掉到 6979）。

频域链里**唯一剩下的厂商 IP 是 `rom_atan_lut_1024`**（相位查表）。它带来一处隐蔽缺陷：该 IP 的 `ena → douta` 需要**两拍**（`.xci` 为 `C_HAS_MEM_OUTPUT_REGS_A=1` + `C_READ_LATENCY_A=1` + `C_HAS_REGCEA=0`），而旧设计两个状态机都按一拍取数 ⇒ 每次拿到上一次查表的值 ⇒ **相位与功率因数是错的**（幅值类不受影响）。旧的手写行为级模型恰好是一拍，把这个缺陷掩盖了；旧工程 `PQM/FPGA/ip/rom_atan_lut_1024` 参数完全相同，所以**这是旧设计在真实硬件上一直存在的缺陷**。修法是把 `ena` 拉宽到两拍、取数挪到新增的捕获状态。

**相位符号约定（已查清，非缺陷）**：仿真里 1 次谐波相位实测 −9000（x100），而按标准 DFT 解析值是 +9000，差 180°。根因是 RFG 引擎 `pl/rtl/RFG/e01_rfg_direct_bin_engine.sv` 用 `phase_negative_sine_q24`，即虚部按 −sin 定义、等价 $e^{-j\omega t}$（与标准 DFT 的 $e^{+j\omega t}$ 共轭）。U、I 走同一引擎、同一约定，故**相对相位差是可信的**，只是整体取反：用户给的 60° 相差，板上显示 **−59.98°**，这是对的。

### 3.7 PS/PL 共享内存 ABI

这是 PS 与 PL 之间唯一的接口（`pl/rtl/PSInterface/pqm_shared_memory_map.vh` 与 `app/pqmshm/pqm_shared_memory_map.h` 两侧同步维护）：

| 项 | 值 |
| --- | --- |
| 基址 / 容量 | `0x40000000`，16384 字 × 32 bit |
| 谐波 bank0 基址字 | `0x400` |
| 谐波 bank1 基址字 | `0xC00` |
| 每条谐波占字 | 4 字（U1 占比 / U2 占比 / 相位 / 标志） |
| 条目数 | 64 条（0..63），帧尾 index `PQM_SHM_HARMONIC_LAST_INDEX = 0x3F` |
| magic | `0x50514D31`（"PQM1"） |

**双 bank 交替**是这里的关键设计：PL 往一个 bank 写整帧，PS 从另一个 bank 读，靠状态字里的 bank 位切换；PS 读完还要做"撕裂检查"——读完数据后序号必须没变，否则这一轮丢弃。这样即使 PS 的读取恰好落在 PL 写帧的中间，也不会读到半新半旧的帧。

**validity 位**（粘滞位，复位后保持）用来把"PL 内部出过事"这件事告诉 PS：

| 位 | 掩码 | 含义 |
| --- | --- | --- |
| bit12 | `0x00001000` | 去零点饱和 |
| bit13 | `0x00002000` | RFG 溢出 |
| bit14 | `0x00004000` | FIFO 溢出 |

任一位置起时，PS 侧把 THD 与 DC 显示成 `--` —— **宁可在界面上显示"没有数据"，也不要把静默错误的数字当成测量结果**。

### 3.8 PS 侧显示换算：模拟市电倍率

PL 报的是 10 V 满量程的真实电压，而演示要让人看到"市电"量级。做法是在 PS 侧乘一个系数 K（`app/pqmui/pqmui_format.c` 的 `PQMUI_ApplySimScale()`，**唯一的换算点**）：

$$K=\frac{220\sqrt2}{8}=38.89,\qquad K^2=1512.43$$

推导：市电 220 V 是**有效值**，峰值为 $220\sqrt2 = 311.13$ V；信号源给 AD7606 的 16 Vpp（峰值 8 V）代表市电 220 V，故 $K = 220\sqrt2/8$。由此 ADC ±10 V（峰值）满量程对应 ±388.90 V，**满量程有效值恰为 275.00 V**，16 Vpp 输入显示 RMS 220.00 V。

> 这条口径在本轮被纠正过：旧口径 `K = 220/8 = 27.5` 把 220 V 当成了峰值，同一路 16 Vpp 输入只显示 RMS 155.6 V。改倍率**只重编了 ARM 应用**，PL 与比特流一个字没动——这正是 §2.2 那条"换算只放 PS 侧"的收益。

## 4 FPGA / Zynq 的优势

这一节只讲**本工程实际吃到**的好处，每条都尽量给出本工程的对应事实。

### 4.1 确定性时序：延迟是常数，不是"通常"

PL 的测量链是一组固定结构的状态机 + 流水线，帧延迟由结构决定，不随 CPU 负载、中断、操作系统调度波动。本工程里这一点被具体量化到拍：

- 采样是**纯时基**的：`pqm_adc_pacer` 不看 ADC 忙闲，25.6 kHz 的周期是 1953 拍，一次采样约占 700 拍；tick 撞上驱动忙时**不重触发**，只置粘滞标志 `adc_tick_pending`。于是"采样率"是一个与硬件握手无关的常数。
- 一帧 RFG 的计算期是确定的：L4/D1 为 **83840 拍**（≈1.68 ms @50 MHz），L16/D8 为 **3464 拍**（`pl/README.md`）。FIFO 深度就是照这个数定的。
- 静态时序可闭合且有报告可查：最新一次实现报告的 **WNS +2.024 ns / WHS +0.046 ns / WPWS +2.500 ns，失败端点 0**，报告原文 `All user specified timing constraints are met.`（`vivado/reports_meas/post_impl_timing_summary.rpt`）。

对照 §1.2：PC 方案能给出"平均"吞吐，但给不出"这一帧一定在这些拍内完成"。

### 4.2 真并行：多通道、多算法同时跑，不抢时间片

PL 里的运算单元是**真实并行**的物理资源，而不是被调度器切分的时间片。本工程的口径是最直接的例子：

- 两个通道（U1、U2）各有独立的零点跟踪器、独立的 RFG 前端（`pqm_rfg_frontend` 内含 2× RFG + 2× 直流累加器），两路**同时**推进，互不排队；
- 时域测量与频域分析**同时**运行在同一个 50 MHz 时钟域里，并行消耗 88 个 DSP（`vivado/reports_meas/post_impl_utilization.rpt`），而不是串行执行再分时复用。

这也是 §5 里 RFG 能靠"折叠 + 并行度 D"换资源—速度权衡的物理前提：在 FPGA 上，"多花一点逻辑"就能真的把周期数降下来。

### 4.3 PL 侧零 CPU 占用

测量链在 PL 里闭环完成，**ARM 一个周期都不花在测量上**。ARM 只做两件事：每 50 ms 读一次共享内存（`app/pqmshm/`），然后把值交给 LVGL 画出来。这个分工带来的直接后果是：

- 界面的帧率与测量链的实时性**解耦**——界面卡一下不影响测量精度，测量链也不需要为界面让路；
- ARM 侧可以随时重编重烧（本工程改倍率、改频域页就是如此），**PL 不必重新综合**（§2.2）。

### 4.4 PS 与 PL 的紧耦合：共享内存 + 双 bank

Zynq 的 PS 与 PL 在同一颗芯片里，通过 AXI 直连。本工程用 AXI BRAM 控制器把 PL 侧的块存储暴露成 PS 的一段线性可寻址窗口（`0x40000000`），于是"PS 读测量结果"退化成"读内存"，没有驱动栈、没有 DMA 描述符、没有中断延迟。

代价是这块存储是**异步双口**的，两侧时钟来自不同晶振（PORTA 归 AXI 100 MHz，PORTB 归 PL 50 MHz），属于真正的跨时钟域。本工程的处理是（`docs/HANDOVER.md` §3.5c）：

- 命令通道经 `pqm_shm_command_capture.v` 做两趟一致性检查后再受理；
- 桥侧修掉 `if (capture_busy) bram_addr = ...` 抢地址却不撤 `bram_we` 的缺陷；
- `pl_resetn` 加复位同步器 `reset_sync_n.v`；
- **残余项如实记录**：3 条 PL→PS 中断仍无同步器；构建时故意没加 `set_clock_groups -asynchronous`，以便跨域路径继续在报告里可见。

### 4.5 可重配置与"工程可复现"

PL 的"可重配置"在本工程体现为两件具体的事：

1. **算法可以整体换代而不用换板**：频域链从厂商 xfft 整体换成自研 RFG，动的是 RTL 与 BD，硬件不变。旧路线在移除前还查实了一个真实缺陷（`fft_result_receiver` 在位反转输出序下，帧尾标志在第 2 个选中频点上就拉高，下游只剩 1023 个频点不进统计），换成自研链后这类"厂商 IP 内部约定"的坑也一起消失了。
2. **构建可复现**：从源码到比特流/启动镜像的每一步都有脚本（§6），并且被验证过是字节可复现的——重建出的 `pqm2_meas.bit` 与之前那次**字节数完全相同**（4,045,673 B）。

### 4.6 相对工控机/DSP 的功耗与体积

同一颗 Zynq 里集成了 CPU 与逻辑，省掉了"工控机 + 采集卡"或"DSP + FPGA"两片方案的板级开销（互联、供电、封装）。**但本工程没有实测功耗，也没有做与工控机/DSP 方案的功耗或体积对比测量**——这里只说明结构上的省法，不给数字。

## 5 RFG 的优势

> **本章的证据来源是另一个研究工程** `C:\Users\zhangtao\Desktop\Goertzel_FPGA`（只读参考），不是 PQM2 本工程测出来的。
> RFG 的加速比/资源数据来自那份工程的 E01 全网格扫描；PQM2 只是把这套引擎按 N=512/K=64 的配置落地。
> 引用处均注明文件名；那份文档自己声明的边界在 §5.5 原样保留。

### 5.1 RFG 是什么：从 Goertzel 到残基折叠

**Goertzel** 是"只算需要的那几个 DFT 频点"的二阶递推（`Goertzel_FPGA/docs/project_learning_guide.md` §4）：

$$\omega_k=\frac{2\pi k}{N},\quad c_k=2\cos(\omega_k),\qquad s[n]=x[n]+c_k s[n-1]-s[n-2]$$

其特征根是 $e^{\pm j\omega_k}$，所以内部状态天然围绕目标频率旋转；窗口结束时由最后两个状态恢复目标 DFT 值或直接算功率 $P_k=s^2[N-1]+s^2[N-2]-c_k s[N-1]s[N-2]$。

相比 FFT，Goertzel 的优势来自**频率选择性**：FFT 要算整个频谱（含大量用不到的频点）并缓存整帧，Goertzel 只为目标频点付出代价。代价是**每个目标频点都有自己的递推状态和系数** —— 要 64 个谐波，就是 64 套递推。

**RFG（Residue-Folded Goertzel，残基折叠 Goertzel）解决的就是这个"每频点一套状态"的问题。** 令 $N = LC$（$L$ 是折叠相数，$C=N/L$ 是短序列长度），把原窗口分成 $L$ 个连续的长度 $C$ 的块，代入 DFT：

$$X[k]=\sum_{c=0}^{C-1}e^{-j2\pi kc/N}\left(\sum_{r=0}^{L-1}x[c+rC]\,e^{-j2\pi kr/L}\right)$$

对整数 bin，令 $q = k \bmod L$，则 $e^{-j2\pi kr/L}=e^{-j2\pi qr/L}$，于是可以**预先形成有限个折叠支路**：

$$y_q[c]=\sum_{r=0}^{L-1}x[c+rC]\,e^{-j2\pi qr/L},\qquad X[k]=\sum_{c=0}^{C-1}y_q[c]\,e^{-j2\pi kc/N}$$

（推导引自 `Goertzel_FPGA/docs/project_learning_guide.md` §5.1。）

### 5.2 它省在哪里

把上面的式子读成硬件结构，省法就清楚了：

1. **递推长度从 N 缩到 C=N/L**。`L=8` 时每个目标频点的递推长度只有原来的 1/8——**寄存器状态数**随之下降，这是最直接的一项。
2. **折叠支路被多个目标 bin 共享**。$q=k\bmod L$ 只取 $L$ 个离散值，所以 $L$ 个折叠支路可以服务任意多个目标频点：**同一条折叠算术被 K 个谐波复用**，而不是每个谐波各搭一套前端。这是"残基折叠"这个名字的实质。
3. **旋转系数只需要 $L$ 个离散角度**（$e^{-j2\pi qr/L}$，$q\in[0,L)$），不需要为每个频点各存一套任意角度的旋转因子——**系数存储**随之下降。
4. **折叠深度 L 与并行度 D 是两个独立旋钮**。L 决定"折多深"（省逻辑与存储），D 决定"铺多少路"（省周期）。这给了设计者一个二维的取舍空间，而不只是"堆 DSP 换速度"。

（工程侧的对应事实：`Goertzel_FPGA/docs/E01/design/architecture.md` 记载 RFG 顶层为"折叠前端 + 内联残差存储 + 唯一后折叠引擎"，各 L 的残差字宽为 L2：2×17、L4：4×18、L8：16×20、L16：32×21 位；输入 Q2.14、旋转系数 Q2.24、输出 32 位含 15 个小数位。）

### 5.3 该项目的实测证据

E01 在**统一口径**下比较三类 FPGA 实现：直接 Goertzel、FFT、以及以折叠因子 L 参数化的 RFG。范围（`Goertzel_FPGA/docs/E01/speedup_study/speedup_study.md`）：

- **5016 个配置**，覆盖 N = 64/128/256/512、K ≤ 63、D ∈ {1,2,4,8}（且 D ≤ K）、RFG 的 L ∈ {2,4,8,16}，合计 **220 个 (N, K) 工况格**；
- 按四条闸门（XSim 通过、布线后时序通过且 WNS ≥ 0、严格保持检查通过、统一精度口径通过）准入 **5015 个**，唯一不合格点是 `scan2/RFG/N512/K7/L4/D4`（WHS = −0.004 ns）；
- 资源取**布局布线后**的实际用量，周期取 50 MHz 下同一测量口径的无停顿帧周期；
- 指标以 LUT/FF/DSP/BRAM18eq 构成等权资源指数 R；横向以同 (N, K) 的 Goertzel D1 为共同基准；
- 全部图件在整张 220 格网格或全部 5015 个准入配置上聚合，**没有任何结论以手工挑选的单个 (N, K) 为依据**。

主要读数（同一文件 §4）：

| 读数 | 数值 |
| --- | --- |
| D=8 时中位纵向加速比 S(v) | Goertzel **7.214**；RFG L2/L4/L8/L16 = **6.925 / 6.694 / 6.292 / 5.744**；FFT **3.135** |
| D=8 时中位并行效率 η | Goertzel **90.179 %**；RFG 四档 86.564/83.673/78.654/71.799 %；FFT **39.184 %** |

### 5.4 适用区间与反转（这一节不能省）

上面那些"多数格"的结论都有明确边界，原文逐条量化（同一文件 §4.4、§4.5）：

- **中等 K 窗口占优，高 K 反转**：216 个可比格中 **161 格（74.5 %）** RFG 升级是两种最优中较便宜的那个；K ≤ 15 的 **56 格全部**成立；medium-K 窗口（K = 16–31）的 64 格中 **55 格**成立（**N ≥ 128 的 48 格全部**成立）。
  但 **K ≥ 50 的 42 格中只有 13 格**成立——反转在工频谐波边界附近发生。
- **反转出现在哪个 N 上不一样**：K ≥ 50 段，N = 128 与 N = 256 各 14/14 组的最便宜升级属 **FFT**；而 N = 512 的 14 组中 **13 组属 RFG**。原文明确写：**"高频场景 FFT 更省"只在 N ≤ 256 成立**，两句话不能互相外推。
- **N = 64 是例外**：medium-K 窗口的 9 个反例格全在 N = 64。
- **家族结论对"资源怎么加权"只是部分稳健**：六种资源权重口径中，五种非退化口径里 RFG 在**四种**占多数；但**只用 LUT 时 FFT 以 109 组反超 RFG 的 106 组**。原文明确："因此不得写成'家族结论对权重完全不敏感'。"
- **"最快"与"最便宜"通常是两个不同配置**：220 格中最快家族全是 RFG L16，但等权最低 J 只有 **146 格**属 L16；**只有 68/220 格**的 J 赢家同时是最快配置，此时它的周期代价中位 1.5737 倍、最大 14.9008 倍。
- **"赢得窄"是常态**：**95/220 格（43.2 %）**的 J 亚军与赢家相差不到 5 %——原文注明这是"明示的描述阈值，不是统计显著性"。

### 5.5 证据边界（原文声明，原样转述）

下面几条是那份文档自己划的界，引用它的数字时**必须一并转述**，否则就是把局部结论当普适结论：

1. **不能写成"所有频点数下 RFG 均优于 FFT"**。原文（`Goertzel_FPGA/docs/E01/speedup_study/speedup_study.md` §4.4 与本报告任务书所引）："E01 现有实例表明，RFG 在部分 N/K 点有更好的增量回报；**K50 等高谐波组可能由 FFT 获得更低 JΔ**。"
2. **JΔ 不是通用标准**。原文 §3.7："J_Δ = (G − 1)/(S − 1) 在文献中没有同名指标"，其形态最接近 AT 与 AT²（Thompson, STOC 1979）与 EDP（Horowitz 等, 1994），但两者都是**非增量**形式；把"扣除基准后的增量"写成比值的方法论锚点在并行计算（Karp–Flatt 串行分数、isoefficiency）。原文把它定位为"**AT 型指标的增量推广**，而不是新提出的通用标准"。**并且原文明确："不能将最低 JΔ 解释为最低功耗"** —— R 是四类器件占用率的等权综合指数，不等于面积、功耗或价格。
3. **"计算可复现不等于应用验收通过"**。原文 §6 与 §5.1 写明：单器件单时钟、每个配置只测一次（**没有重复测量，因此没有误差棒、置信区间或 p 值**）；**没有测启动间隔**，因此不称持续吞吐率；帧延迟不等于帧接收间隔；"最大允许处理延迟尚未确定；'支持 50 次谐波'的点位覆盖不等于已经满足完整电网测量标准"。
4. **RFG 的折叠本身不是那份工程提出的新架构**。原文 §2.1 明确：折叠/时间复用递归 DFT 属于 sliding DFT、running DFT、recursive DFT、resource sharing 这一谱系，"是以折叠因子参数化的一个实例，不是本实验提出的新架构"；Goertzel 与 FFT 之间"周期代价随 K 增长的斜率不同"也只是教科书级的 $K\cdot N$ 乘加与 $N\log_2 N$ 对比。**那份报告的新颖性落在测量域**（统一口径下的后布线全网格比较），不是架构发明。
5. **RFG 依赖整数 bin**。原文 §5.2：折叠只在 $k$ 为整数时才能用有限集合的 $q=k\bmod L$ 表示全部折叠权重；频偏使目标 bin 变为非整数时，"朴素分数折叠的预处理乘法会吃掉短递推节省的开销"。那份工程的应对路线是"估计基频相位 → 同步重采样恢复固定网格 → 仍用固定系数 RFG"，而**这条频偏适应链路的结论限于其模型与已覆盖工况，尚未做完整定点和 RTL/硬件验证**（原文 §1 的两条证据层次表）。
6. **DSP 用量恒等于 D 是构造约束不是观测巧合**：当前 RTL 每个 lane 实例化一个单 DSP 乘法原子，`C_D` 只允许取 1/2/4/8。因此 DSP 项不携带独立于 D 的信息，η 也不度量 DSP 的分配效率（原文 §3.2、§5.4）。

| L（折叠度） | **4** | 同上 `C_L=4` |
| 一帧对应 | 一个 50 Hz 周期 = 512 点 @ 25.6 kHz | `pl/README.md` |

需要说清的对应关系：**PQM2 是这套 RFG 的一个工程落地实例，不是它的验证平台**。研究工程负责"哪条算法路线能保留 RFG 的好处"；PQM2 负责"把其中一个配置（L4）在真实硬件上跑成一台仪器"。所以：

- §5.3 那些加速比/资源数字**不是 PQM2 测出来的**，也不能当成 PQM2 的性能指标；
- 反过来，PQM2 的板上实测（§7）**也不是对 RFG 算法本身的验收**——它验证的是整条测量链在这块板上、对这组激励给出的数值对不对。

## 6 工作流程

### 6.1 从源码到上板

完整链路（命令与说明见 `README.md` 的「构建 / 仿真 / 烧录」）：

| 步 | 做什么 | 产物 | 典型耗时 |
| --- | --- | --- | --- |
| 1 | **Vivado**：官方基线 BD（`upgrade_ip`）+ 共享内存 + PL 测量链 → 综合 + 实现 + 比特流 + XSA | `vivado/pqm2_meas.bit`、`vivado/pqm2_meas.xsa` | 全量 20–25 分钟（其中 26 个 IP/BD 的 OOC 综合约 12 分钟是固定开销） |
| 2 | **Vitis**：从 XSA 生成工作区、BSP，同步 `app/` 源码，编译应用 | `pqm2_app.elf`，以及平台自带的 `fsbl.elf` | 约 2 分钟 |
| 3 | **仿真回归**：`scripts/run_xsim.ps1 -All` | 日志中的 `PASS: <用例>` | 全量约 2 分钟（系统级用例 `pqm_pl_top` 单独约 95 秒）；单模块 8–14 秒 |
| 4 | **JTAG 烧录与读值**：复位系统 → 编程 PL → `ps7_init` → 下载 ELF → 等 10 s → 回读显示通路寄存器 → 抓共享内存 | `export/board_meas.log`、`export/shm_words_1/2.txt` | 约 1 分钟 |
| 5 | **SD 卡启动镜像**（可选）：`bootgen` 合成 FSBL + 比特流 + 应用 ELF | `BOOT.BIN` | 约 1 分钟 |

两个必须守住的约束：

- **Vivado 的进程工作目录必须是 `vivado/build_meas`**，否则 PS7 会把 `NA/` 写进源码根。
- **换比特流必须同时换 ELF**。`vivado/pqm2_meas.xsa` 对应的比特流才有 `axi_gpio_0`(0x41200000)、`clk_wiz_0`(0x43C00000) 这两个应用会访问的外设；拿只有视频段的旧 XSA 编出的 ELF 会去访问不存在的外设并挂死，**屏幕全黑只剩背光**（`docs/HANDOVER.md` §3.4 记录了这次事故的完整根因）。

### 6.2 仿真先行、单元可回归

本工程的判定基线是**仿真**，不是板上的数（信号源可换、波形由用户控制）。回归基础设施 `scripts/run_xsim.ps1` 的约定：

- 命名：`pl/rtl/<组>/<模块>.v` ↔ `pl/sim/<组>/tb_<模块>.v`，**组名必须一致**；
- 判定：必须看日志里的 `PASS: <用例名>`，**不能看退出码**——xsim 的 `-runall` 即使遇到 `$fatal` 仍返回 0；
- 用例需要额外源或向量时，在 `pl/sim/<组>/tb_<用例>.models.txt` 里逐行列目录，**该文件必须用 CRLF**（用 LF 时 Windows PowerShell 5.1 会把它读成一整行、吞掉第一项）；
- 数值检查必须带 `^actual === 1'bx` 守卫——Verilog 里 `if(X)` 为假，范围比较会**静默放行**，让断言"真空通过"。

当前状态：**30/30 全绿**（系统级用例 `pqm_pl_top` 覆盖采样率、零点收敛、RFG 输入契约、谐波帧结构、快照提交、共享内存 ABI 回读）。

### 6.3 证据分层纪律

这套纪律来自两条独立的实践（PQM2 自身，以及 `Goertzel_FPGA` 的 E01/E02），要点是**不要用一层证据替代另一层**：

| 证据层 | 能回答 | 不能回答 |
| --- | --- | --- |
| 参考模型（浮点/双精度） | 公式、算法结构、变量隔离是否合理 | 位宽、溢出、真实综合资源 |
| 定点模型 | Q 格式、舍入、饱和、误差预算是否可接受 | 实际 RTL 时序与综合利用率 |
| RTL + XSim | 位真、握手、背压、周期、溢出行为 | 未覆盖输入工况的统计泛化、物理时序 |
| Vivado 综合/实现报告 | LUT/FF/DSP/BRAM、Fmax、WNS/WHS | 功能正确性 |

具体到本工程的两条硬经验：

- **XSim 通过只证明给定场景的功能**；资源和时序**只能**引用 Vivado 报告（`Goertzel_FPGA/docs/E02/rtl_optimization_reference.md` §8.3）。
- **资源下降只能由相同条件下的报告对比证明**：源码删减不保证资源下降——综合器可能早已把无用逻辑剪掉。同理，**改结构前先确认它不是"看起来更省"**。

- 板子：Zynq XC7Z020-CLG400-2，JTAG（Digilent JTAG-HS1）连接，PL 时钟 50 MHz；

### 8.1 硬约束（工程层面）

1. 旧工程 `C:\Users\zhangtao\Desktop\PQM` **只读参考**，不修改；另外三个只读目录是 `B-20260803`、`zynq7020-examples`、`D:\zt\DeepSeek-Harness`。

3. **数值正确性靠仿真证明，不拿板上的数当验收** —— 信号源可换、波形由用户控制。板子可用、烧录与连板不受限，但"板上读到某个数"仍然不等于验收通过。

### 8.2 已知的口径限制

- **过零测频在畸变波形下给的是穿越率，不是基波频率**（§3.4）。本工程实测过一次强畸变输入读到 249.96 Hz。该次波形是操作者自己改的、明确不算缺陷，所以**没有改**；但这是一条真实限制，若要覆盖畸变波形应改用 RFG 的 1 号 bin 定频率。
- **精度口径**：PQM2 的 THD/相位等指标来自谐波占比与 atan2，输出只用于比值与角度，因此 `pqm_rfg_scale` 的 >>10 缩放是尺度无关的。**本工程没有做绝对幅值精度的标定**（板上数值与信号源设置的一致性见 §7.2，但那是端到端比对，不是可溯源标定）。
- **`S_AXIS_SAMPLES` 样本流路径空置**：`pqm_axis_sample_stream.v` 存在但未被实例化，`pqm_pl_top` 不导出逐样本数据。若要做原始波形上传/录波，需要接上这条路径。

### 8.3 CDC 的残余项

- 3 条 PL→PS 中断**仍无同步器**；
- 构建时**故意没加** `set_clock_groups -asynchronous`，以便跨域路径继续在报告里可见。若哪天要正式收敛 STA，需要一并处理（并接受跨域路径从报告里消失）。

### 8.4 尚未在板上验证的项

（`docs/BOARD_VERIFY.md` §5）小量程页、谐波翻页、`Freeze`/`Resume`；以及边界条件：阈值附近的小信号、上电瞬态、`drop_count` 在异常激励下的行为。这些都不是已知缺陷，只是**还没看**。

### 8.5 RFG 相关的边界（再次强调）

引用的那份研究工程的结论**只在它自己声明的范围内成立**（§5.5）：局部优势不能写成普适结论（K ≥ 50 与 N = 64 会反转；只用 LUT 加权时 FFT 反超）；JΔ 是该项目定义的**探索性增量评价指标**、不是既有通用 FPGA 标准，**最低 JΔ 不等于最低功耗**；**计算可复现不等于应用验收通过**（单器件单时钟、无重复测量、未测启动间隔、未设定最大允许延迟）。PQM2 用的是这套引擎的 **L4 配置**，它对 RFG 算法的验证只到"在真实硬件上跑通并给出正确数值"这一层。
