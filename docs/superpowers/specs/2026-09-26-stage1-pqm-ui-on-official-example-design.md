# 阶段 1：在官方例程上重建 PQM 界面（设计）

日期：2026-09-26
工程：`C:\Users\zhangtao\Desktop\PQM2`

## 1 目标

以官方例程 `37_zynq_lvgl` 为基线，把旧工程 PQM 的**界面布局、交互与显示效果**按其规格重新实现，使目标板上出现与旧 PQM 等价的画面。

阶段 1 的验收标准（已确认）：

- 时域页与频域页都能显示；
- 触摸能切换页面、能冻结；
- 参数、波形、谐波由内置假数据填满，数字随时间变化；
- 画面与旧 PQM 界面**严格像素级等价**。

## 2 范围

**做**：

- 使用官方比特流（由 `hw/system_wrapper.xsa` 生成），PL 不做任何改动；
- 使用官方 PS 驱动、官方 LVGL 8.2.0 与官方 `main.c` 的初始化顺序；
- 新写界面层、工程量格式化层与假数据源。

**不做**：

- 不引入 FreeRTOS；
- 不接共享内存、AD7606、AXI DMA；
- 不改 PL，不用 Vivado；
- 不"顺带改进"旧界面的观感（见 §6）。

## 3 为什么不能沿用旧 PQM 的 PS 代码

旧 PQM 的 PS 端整体绑定在它自己的 PL 硬件清单上，与官方比特流不匹配，分三类：

1. **编译期就缺符号**。旧 PS 代码引用 4 个只在旧平台存在的 `XPAR_*`：`XPAR_AXI_BRAM_CTRL_0_S_AXI_BASEADDR`（`pqm_platform.c`）、`XPAR_AXIDMA_0_DEVICE_ID` 与 `XPAR_FABRIC_AXIDMA_0_VEC_ID`（`pqm_dma.c`）、`XPAR_FABRIC_AXIVDMA_0_VEC_ID`（`pqm_video.c`）。官方 PL 没有 BRAM 控制器与 AXI DMA，平台头文件里也就没有这些符号。
2. **启动即死**。旧 `main()` 第一件事是校验 `0x40000000` 的共享内存 magic/ABI，失败即 `pqm_platform_fatal()`（打印、写标记、原地自旋）。官方 PL 上没有该内存。
3. **同一 IP、两套不兼容的配置**。`axi_vdma_0` 都在 `0x43000000`，但旧工程是 16 位（RGB565）双缓冲 @ `0x3E000000`、靠帧完成中断换帧；官方是 24 位（RGB888）单缓冲 @ `0x01100000`、自由运行。

旧工程里唯一与本工程兼容的是**界面层与格式化层**——它们只依赖 `lvgl.h` 与 `stdint`/`stdbool`，不引用任何硬件。本工程不复用其代码，只复用其规格。

## 4 代码风格约定

界面层按官方例程的组织方式重写，与原 PQM 的差异：

| 维度 | 旧 PQM | 本工程 |
| --- | --- | --- |
| 状态传递 | 大 `pqm_ui_t` 上下文结构体逐层传参 | 文件级 `static` 对象（同官方 `lv_port_disp_template.c`） |
| 整数类型 | `uint32_t` 等 | `u8`/`u16`/`u32`（`xil_types.h`） |
| 函数命名 | `pqm_ui_time_refresh_measurement` | 模块前缀 + 驼峰，如 `PQMUI_TimeRefreshMeasurement` |
| 头文件守卫 | `PQM_UI_H` | `__PQMUI_TIME_H__` |
| 分层 | driver / service / ui 三层 + RTOS 任务 | 模块目录 + `main` 顺序初始化 + `while(1)` |
| 依赖 | `FreeRTOS.h`、`xaxivdma.h` | 只依赖 `lvgl.h` 与 `xil_types.h` |

## 6 等价性口径：只改三处，保留四处

阶段 1 要求严格像素级等价，因此只做不改变画面的代码层面整理：

1. 时域页横轴 `20 ms` 抽成命名常量并注明"真实时基待 PL 采样率确定"，显示文本不变。
2. 告警码解码把 1~4 显式写出，5~7 单独说明；PL 只定义 0~4，渲染结果与旧实现完全一致。
3. 频域页右面板中复用同一个数组存放"谐波详情"的做法拆成两组独立对象，属内部结构，不出现在画面上。

以下四处**有意保留原样**，包括其中已知的不一致：

1. 频域页 `Fundamental` 一行显示的是频率（单位 Hz）。
2. 频域页右面板 8 行不分组，前 5 行与后 3 行语义不同但外观连排。
3. 窗口标签显示 `H0 - H25`，而详情区显示的是 H1（因 H0 为直流）——标签与详情不对应，保留。
4. 轴标与图表边界存在数像素偏移，保留原坐标。

## 8 验收与观测点

| 现象 | 观测手段 | 通过判据 |
| --- | --- | --- |
| 屏幕不出图 | 读 VDMA `0x43000004`、`0x4300005C`，VTC `0x43C10004` | 与官方例程跑通值对齐：`SR=0x00011000`、MM2S 起始 `0x01100000`、`VTC=0x00013000` |
| 出图但等价性存疑 | dump `0x01100000` 起 1 152 000 字节，还原成 PNG，与 `../PQM/ARM/export/fb0.png` 并排比较 | 布局逐块重合 |
| 触摸不响应 | 读 `tp_dev.sta` 与 AXI GPIO 的 LCD ID | LCD ID 决定 `vd_mode`，取值异常则时序不对 |
| 编译失败 | 直接调用 `xsct.bat` 的完整日志 | 56 个 LVGL 符号（含 `LV_*` 宏）已核在 8.2.0 中无缺失 |

翻页可自动验证：点击 `Spectrum` 前后各 dump 一次帧缓存，两张 PNG 不同即证明切换生效。

## 10 风险

1. `main.c` 与 port 层由 GBK 重写为 UTF-8，需确认 ARM gcc 对 UTF-8 中文注释无告警级问题（旧 PQM 的 UTF-8 源文件已在此工具链上编译通过）。
2. LVGL 8.2.0 与旧 PQM 使用的 8.3.11 存在版本差。符号级已核对无缺失，但默认主题与字体渲染的细微差异可能造成画面与对照图存在个别像素级不同；此类差异不视为等价性失败。
3. 官方 `lv_conf.h` 的 `LV_COLOR_DEPTH` 为 32，帧缓存为每像素 3 字节 RGB888；对照图来自 16 位 RGB565 帧缓存，颜色会有量化差异。
